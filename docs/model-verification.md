## 原检测流程（verification-v3，2026-10-15）

页面默认启用分词指纹。每个账号／模型组合执行每轮 6 项随机能力题和 1 项同题复测，再执行一次 10 请求的指纹采集；总预算为 `7 × 轮次 + 10`。关闭指纹时执行原有能力与协议检查；若选有官方参考，只比较同题正确性及原始用量，并明确未采集分词差分。参考账号也进入真实请求矩阵并计入预算，最多 20 个账号、20 个模型、100 个组合；不会调用未选择账号或自动重测历史任务。

1. **选择对照**：展开「官方 API 对照（可选）」，选择支持相同模型的官方 API 账号，再选择共同模型。只列出 HTTPS 精确官方域名且未被排除的 API 账号，拒绝相似域名、自带用户名／密码及非标准端口；后端仍按实际解析的端点决定来源。OAuth 走固定官方传输，可确认本次来源，但不作为 API 对照。
2. **执行采样**：基准、中文、英文、代码、Unicode 五类固定文本各请求两次。保存每项题目、采样目的、原文、输入用量、请求 ID、协议、型号和错误；运行中实时显示等待、已采集与未执行。采样回答不参与能力评分。
3. **检查稳定性**：重复输入的 Token 数、返回型号和协议必须一致，才计算各文本减去基准文本后的差分。缺失元数据、请求未完成、重复不稳定分别展示；所有文本均报相同用量的无区分度结果不可用于相符判定。
4. **比较官方参考**：只比较同任务、同请求模型、同指纹版本、同协议、返回型号与请求一致的完整稳定样本。报告列出各文本的当前差分、参考差分及两侧差值。固定模板开销不会单独造成差分异常；任一完整参考有差异不能被另一相符参考覆盖，部分参考失败单独保留。缺少凭据和官方授权失败显示未完成，不显示来源已确认。
5. **阅读结果与历史**：能力、采样和官方对照独立展示。未选择参考显示「官方对照未进行」，已选择但不可比显示「官方对照未完成」，数值不同显示「官方对照存在差异」。不会把没有进行的检查算作身份异常。历史报告保留原证据；缺少结构化对照状态时说明记录不完整，不沿用笼统的身份不足告警，也不补造新采样。顶部「检测历史」可按需加载历史明细。

OpenAI 使用现有 Responses／兼容传输，Claude 使用 Anthropic Messages，Gemini 使用原生生成协议；三者复用相同采样与判断，缺失字段不补零。接口用量由上游报告；动态提示词、缓存计数口径、文本处理及混合路由可能影响采样，应核对明细。相同分词器常被多个型号共享，因此分词相符不能证明具体模型权重，也不能代表其他时间或生产路径。当前不使用未校准的行为概率或第三方旧型号基线。

具体参考方法：

- [modelprint 的重复中文测量](https://github.com/unclecode/modelprint/blob/main/probes/tok-chinese.js)与[模板开销测量](https://github.com/unclecode/modelprint/blob/main/probes/template-offset.js)：采用重复输入和减去基准用量的做法，扩展为四类文本。
- [veridrop 的官方 Token 对照](https://github.com/canarybyte/veridrop/blob/main/src/relay_detector/protocols/openai/detectors/token_parity.py)：参考显式官方基线；无基线时独立展示，不捏造认证。其 [Claude signature 检测](https://github.com/canarybyte/veridrop/blob/main/src/relay_detector/protocols/anthropic/detectors/thinking_signature.py)仅判断字段存在和长度，不具有密码学验证能力，未采纳为身份认证。
- [llm-fingerprint-detector 的判定](https://github.com/ToseaAI/llm-fingerprint-detector/blob/main/src/verdict.ts)：参考不足样本和不确定结论的分离；其分布判定需要大量采样与校准，未用少量能力题冒充统计分类器。

## 本轮实施目标

替换普通模型检测的可编辑题库和型号白名单，提供自动执行的真实性证据与推理能力检测。账号绑定、凭据隔离、人工取消、上游排除、历史结果读取沿用现有边界。动画质量与接入糖果题保持各自职责。

验收范围：

- 移除题库配置界面及写入 API，新检测不依赖已保存的自定义题库；保留旧数据和历史结果。
- 支持账号模型列表中的新型号，不以旧画像名单限制选择；平台与 OAuth 不兼容时明确拒绝。
- 使用版本化内置随机推理题、输出契约与重复检测，保存逐项问题、预期、响应、判定和请求状态；格式包装不改变答案。
- 真实性独立展示来源、返回型号、协议与重复请求证据；第三方字段、签名存在性、Token 数和模型自报身份不构成认证。
- 官方来源与模型身份分开；第三方接口无可信基线时不能显示已证实。覆盖映射别名、缺失元数据、混合路由线索与能力不支持。
- 超时、限流、权限失败、流式中断、空回复、取消与错误答案分开处理；保留部分结果，不无限重试、不自动改调度。
- 简化选择与结果操作，提供请求量提示、实时状态、取消、重试与证据详情；保持移动端、键盘、加载和失败行为。
- 完成受影响 Go 竞态/vet、前端行为测试/typecheck/lint/format、构建和适用浏览器验证，记录实际覆盖范围。

| `evidence_mismatch` | 存在待核对差异 | 第三方返回型号存在差异，或任一可比官方结果的正确性／输入 Token 不同；明确提示别名、网关提示词、采样等可能原因，不断言假模型 |
| `insufficient_evidence` | 身份依据不足 | 没有可用官方对照，或只有部分比较／缺少型号或用量；提供同任务选择官方 API 账号及补齐证据的说明 |
| `inconclusive` | 身份检测未完成 | 尚无有效模型回答；先处理请求错误，失败不算模型身份异常 |

只比较已经选入本任务的账号，不自动调用未选择账号、不增加检测请求。OAuth 因系统提示词和传输不同仍不作为 API 对照。一份相符对照不得覆盖另一份差异证据，失败项与未执行项不参与一致性计算。旧报告不重新计分或补造认证，显示中性的身份依据不足及重新检测说明；具体原因同时展示在结果行和证据弹窗顶部。
