# 调度策略与算法审查记录

审查范围包括策略保存与执行契约、健康证据与评分、熔断和恢复、成本与权重、多分组容量分配、并发写回保护、巡检编排及分组分配展示。审查基于当前工作区，保留已有未提交改动；测试使用临时数据库和隔离 HTTP 服务，没有连接生产数据库或真实上游。

## 已复现并修复的问题

| 级别 | 触发条件及影响 | 修复与回归 |
| --- | --- | --- |
| P1 | 长期评分窗口小于独立安全规则窗口时，网关熔断、慢响应确认、连续失败、自动处置或恢复成功数无法达到配置阈值。 | 读取各规则所需的最大安全证据窗口，评分及性能统计仍使用各自窗口；`routing/__tests__/safety_window_test.go`。 |
| P1 | 已熔断账号没有熔断后的新样本时，会把熔断前的成功流量或探针用于恢复。 | 已记录本次熔断起点时，所有恢复证据必须严格晚于该起点；`routing/__tests__/recovery_evidence_test.go`。 |
| P1 | 恢复同时修改并发时，参数接口返回成功但没有实际生效，也可能继续启用账号，造成旧并发突破预算。 | 启用前强制读回并发，失败保持暂停，同批相同参数也逐项确认；`routingwrite/__tests__/recovery_confirmation_test.go`。 |
| P1 | 调度等待变更租约或远端读取期间，运行模式、字段开关或策略已改变，仍使用旧授权写入或删除。 | 取得租约后、批次实际提交前及自动删除前复核模式与完整策略，变化时停止旧目标；`routingwrite/__tests__/policy_revalidation_test.go`、`write_authorization_test.go`。 |
| P1 | 关闭接管全部账号时，计算完成后的外部修改没有与托管基线重新比较；已交还状态在后续查询中被忽略，旧目标可能再次覆盖人工修改。 | 使用新鲜远端值核对已托管字段，保留外部值；按 ID 查询持续识别已交还状态，阻止旧目标及自动基线恢复重新接管；`routingwrite/__tests__/external_control_test.go`、`business/__tests__/routing_ownership_lookup_test.go`。 |
| P1 | 跨上游写入只核对各自上游额度，重复使用全局余量；例如总量 8、上限 10，两账号分别从 4 增至 6，最终达到 12。 | 锁定全局库存并复核远端快照，在同一互斥区提交全局与上游预留；覆盖同批、独立任务、分组开启扩容、未知及未同步库存、未确认缩容；`routingwrite/__tests__/global_capacity_test.go`。 |
| P1 | 写回预算把人工暂停账号当成零容量，与算法保留其配置并发的规则不一致，可能侵占其预留额度。 | 仅为已确认的等待并发额度暂停释放保留量，全局与上游预算使用同一规则；独立超额下调仍按实际可调度容量判断；`routingwrite/__tests__/global_capacity_test.go`。 |
| P1 | 自动交还控制权恢复原基线时绕过预算，与同批扩容一起执行可突破并发上限。 | 自动交还纳入容量计划与增长预留，额度不足保持等待；显式人工恢复保持原有操作语义；`routingwrite/__tests__/global_capacity_test.go`。 |
| P1 | 开户只持有上游 Key 租约，可能在调度快照读取后创建新账号，占用同一批次已预留的容量。 | 新建账号与并发写回共用容量租约，一次性取得资源，覆盖可调度及暂停新建；`onboarding/__tests__/capacity_lease_test.go`。工作台导入已有管理目标租约互斥。 |
| P2 | 评分历史范围短于当前证据有效期时，空历史评分覆盖仍有效的当前样本，显示零分或无样本。 | 历史没有有效评分样本时回退当前有效证据；`routing/__tests__/evidence_history_test.go`。 |
| P2 | 等待并发额度的账号原配置大于全局剩余容量时，虽有可用正整数容量仍永久等待。 | 先把暂停账号并发调整到可用容量，确认后再恢复；零余量不写零；`routing/__tests__/recovery_budget_test.go`。 |
| P2 | 两个降级参数可保存至 100 万，调度引擎却只接受 10 万，导致保存后所有调度计算失败。 | 统一 `degrade.priority_step` 和 `degrade.min_load_factor` 的执行范围；`routing/__tests__/policy_execution_test.go`。 |
| P2 | 全局均衡策略允许在页面输入价格占比 0，但保存接口拒绝，与分组覆盖及调度算法不一致。 | 接受闭区间 0 到 1，保留越界拒绝与版本不变校验；`routing/__tests__/policy_execution_test.go`。 |
| P2 | 仓库适配器没有专用容量库存接口，且仅启用独立上游下调时，范围计算漏读范围外保留容量。 | 独立下调也读取全局库存；`routing/__tests__/reduction_scope_test.go`。 |
| P2 | 分组并发只读取本轮变更目标，无需调整时丢失已确认容量；未知、不限流及汇总溢出可能被显示成有限总量。 | 回退当前配置，暂停容量为 0，未知或不限流总量为 `null`，使用精确整数解析并同步前端契约；`business/__tests__/group_allocation_capacity_test.go` 与分组详情前端回归。 |
| P2 | 自动处置计算晚于决策组装，实际目标有处置动作，但任务决策和持久化决策没有该动作。 | 在组装最终决策前完成处置计算，目标和决策同时记录动作；`routing/__tests__/safety_window_test.go`。 |

上述缺陷均先通过稳定失败用例复现，再完成修复。原有运行模式、人工优先位、成本墙、健康确认、有限缓存、单账号下限、写入冷却及独立下调边界沿用当前规则。

容量保护约束 Console 内的自动写入与并行开户，不替代上游实际限流。绕过 Console 直接修改远端账号的操作不受本地租约控制；未关联的外部消费者也不能由本地配置库存准确计量。
