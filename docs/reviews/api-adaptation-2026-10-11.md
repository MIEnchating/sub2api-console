# API 适配：输入校验与请求身份（2026-10-11）

本轮范围为 `backend/internal/api` 的剩余逐文件审查和已复现问题。日志冻结；本轮只修改两个接口的 JSON 绑定和 `requestActor`，新增三个独立回归文件。现有工作区其他功能改动保留，不计为本轮成果。

## 已复现与修复

1. 失效上游绑定清理使用 `ShouldBindJSON`，接受未知字段、尾随对象、错误或缺失 Content-Type。旧实现四种请求均返回 200，并实际删除绑定及身份、写入审计。改用统一 `bindRequestJSON` 后均返回 422，绑定和身份保留，不写清理审计。
2. 账号分组修改也绕过严格解析。相同四类异常请求在旧实现中进入业务预检，隔离配置下返回管理目标缺失的 409；现于预检前返回 422。原有稳定 ID、目标版本、分组数量和业务预检保留。
3. Cookie 鉴权已取得 `session_user`，写接口却再次读取会话。请求通过鉴权后会话恰好撤销时，旧实现仍完成操作，但操作者退化为 `console`。现在复用本次请求的已鉴权身份；撤销后的下一请求仍返回 401。常规 Cookie 写请求每次解析操作者减少一次 `SessionUser` 数据库读取，Bearer 及 Bearer 携带 Cookie 的既有身份规则保留。未缓存跨请求或 SSE 的鉴权结果。

回归使用临时 SQLite、真实配置库、业务库和路由；会话用例仅在存储读取边界协调撤销，不替换鉴权或写入逻辑。覆盖 Cookie、Bearer、混合凭据及失效会话，无真实上游请求。
