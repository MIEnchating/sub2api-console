# 调度并发预算修复（2026-09-07）

本专项已完成调度策略审查第 5/6 项，生产编辑结束。根代理可继续最终全仓 `go test -race ./...` 与集成检查。前端 App 分配范围也已结束，详见 `frontend-app-accounts-review-2026-09-07.md`。

## 已修复

1. 多个主分组各自按完整上限扩容，导致全局目标总额越界。所有主分组共享一份按稳定账号 ID 去重的容量预算；按稳定分组顺序消费余量。
2. 扩容量先受限、随后补齐单账号下限，仍会突破全局预算。最终增加量也受剩余容量限制；无法满足下限时，在账号原因及计算结果配置错误中明确提示调整全局上限或单账号下限。
3. 按账号或分组局部重算时，额外只读全局容量，保留人工保护、暂停及未启用伸缩分组的容量，实际写入仍限于原 scope。全局容量读取失败时，在持久化之前返回错误。
4. 重复分组成员及两次库存读取按同一账号的最大已观察并发去重，防止后一次较小快照制造虚假余量；容量求和使用饱和加法，防止整数溢出。
5. 本轮拟缩容不会提前释放给其他账号扩容，避免冷却保护或远端写入失败导致实际容量超标。

改动集中于 `backend/internal/routing/service.go` 的 `Calculate` 容量读取衔接、`assignAccountPlacements`、`applyScaling` 及容量辅助函数。未修改根代理负责的价格评分、权重算法、策略版本或健康状态规则；同文件内这些并发改动均予保留。
