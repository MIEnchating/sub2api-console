# 账号控制及同类慢接口修复（2026-10-14）

本轮围绕用户反馈的账号熔断/恢复等待，检查控制请求、任务执行、本地展示查询、SSE 初始化、同类账号维护、列表/目录、任务/日志及外部管理 API 的等待路径。基线提交为 `bd000ba5a7e9bc6ff16e0b0334bb801e96d48f0c`，工作区原有会话有效期、异常探活详情等并行改动不归入本轮成果。

## 结论与改动

熔断/恢复需要远端写入、回读和本地提交，恢复还包含错误清理及运行态复位；这些远端往返属于必要操作。本轮确认的非必要等待来自操作路径误用展示详情、提交后构建无返回用途的整套策略，以及列表重复解析元数据。没有用缩短超时、移除回读或提前报告成功掩盖等待。

| 路径 | 确认的问题与处理 |
| --- | --- |
| `/accounts/:id/control` 及所有共用 `accountMutationPreflight` 的入口 | 仅检查账号存在却加载完整详情、稳定性、健康历史、绑定、应用错误。改为一次按主键查询身份及人工控制状态。覆盖控制、模型、字段同步、账号设置、手动控制、分组、成本墙、分组锁定预检。 |

## 其余同类路径核对

- 前端任务状态使用 500 ms 轮询；任务结束主动使相关资源失效，不需要等待账号列表的 30 秒周期。React Query 默认仅立即重取活跃查询。保留资源失效以避免显示过期策略/分组。
- 任务列表使用 `ListConsoleSummaries`，限制最近 20 条；任务详情按 ID 获取。展示名称按所需 ID 批量查询，不加载全账号详情。
- 日志分页已有条件缓存、读取合并和冷读并发限制；本轮未发现与账号控制相同的详情预检问题，未重开历史已验收日志优化。
- 分组/目录已有摘要入口；真实业务列表继续返回业务记录，不以字典缺失隐藏记录。
- 账号工作台线上目录使用 `VisitAccounts` 分页访问；它的远端时延不能用本地状态替换。保留管理目标复核。
- New API 价格目录已限制四个并发上游读取及整体期限；管理端、鉴权、Uptime Kuma 客户端均设置超时。未修改重试及外部写入语义。
- 账号任务与巡检使用各自任务执行组；共享账号/管理目标租约保证操作安全。自动巡检已有让位于手工操作的机制。没有证据支持取消互斥或并发写同一账号。

本轮没有逐个执行真实远端写操作压测，也不把静态检查结论宣称为全部生产接口无延迟。恢复的 `/clear-error` 与 `/recover-state` 保留原有顺序；并发安全缺乏上游契约依据。

## 回归与测量

- 隔离数据库中移除展示证据表，旧控制提交、设置提交、模型发现提交均失败；改后成功。受鉴权保护的分组锁定同样不依赖展示历史。
- 移除无关分组展示表，旧的已确认控制提交返回错误；改后提交成功且调度开关与读回一致。
- SSE 回归覆盖无展示稳定性表时返回首个快照、选择含缺失账号时返回 404；批量 ID 查询覆盖空集合、重复、多账号、缺失、无效 ID 和取消。
- 会话撤销回归改为在新的轻量预检边界撤销真实会话，继续保护首请求保留认证身份、下一请求拒绝，以及只记录一次审计。
- `BenchmarkAccountControlState` 新增 `mutation-snapshot` 对照。单账号附带 64 KiB 元数据时，旧详情约 7.09 ms、1.54 MB 分配；轻量快照约 0.039 ms、648 B。20 个大元数据账号的列表投影由约 26.2 ms、8.55 MB 变为约 16.6 ms、5.30 MB。均为隔离 SQLite 微基准，不能推算线上端到端或 PostgreSQL 收益。
