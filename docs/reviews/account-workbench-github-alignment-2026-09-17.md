### 2026-09-20 授权流程核对与协议替换

- 原项目 `src/workbench-server.mjs` 的登录项经 `src/console-server.mjs` 调用 `src/protocol-login.mjs`。`loginChatgptWeb` 通过 HTTP 获取 CSRF 与登录跳转，提交密码或邮箱验证码，按返回状态完成 TOTP；`runCodexOauth` / `finishCodexOauth` 通过会话与工作区选择取得 OAuth 回调，再交换授权码。这是协议登录，正常自动授权流程不要求用户操作 Chromium 页面。
- 原项目 `dynamicSentinelTokens` 和 `src/tls-transport.mjs` 使用 TLS 指纹传输及动态 Sentinel 安全令牌；实现依赖 Python `curl_cffi` 与本地 JavaScript SDK 运行环境。这些依赖不等于交互式浏览器登录，也不能在 Go 移植中用空令牌或仅复制接口地址代替。
- 修复前 Console 的 `backend/internal/accountworkbench/run_oauth.go` 调用 `s.browser.OpenOAuth`，打开后无条件设置 `waiting_input`、`BrowserReady=true` 和“请完成官方登录页面中的验证”；`login_assistance.go` 再操作浏览器表单。这个实现偏差同时影响导入和自动维护中的重新授权。
- 已删除工作台的 `OpenOAuth`、截图和浏览器输入调用、启动检查以及前端 `RunBrowser`。导入和维护重新授权均使用同一 Go 协议流程；JSON / RT 路径继续复用原有身份验证及私有保存机制。
- TLS 使用 Go uTLS 的 Chrome 133 profile，HTTP/2 使用 Go HTTP/2 客户端；与参考项目默认 Chrome 146 有明确差异。固定解析官方站点和代理，连接失败不切换代理、不重发提交。Cookie jar 私有且使用公共后缀规则；回调只解析固定 localhost 地址，不实际访问。
- 官方 Sentinel 脚本由 Go `goja` 解释器执行，DOM/定时器/iframe 消息接口在本地兼容层提供；没有 Node、Python 或 Chromium 运行依赖。只允许安全 SDK 请求固定官方 requirements 端点，并限制执行时间；网络接口不向 SDK 暴露文件系统、进程、密码或授权码。官方脚本版本更新或不支持的挑战会返回失败，不回退浏览器。
- 2026-09-20 实际公开网络检查：Go 客户端成功读取官方 CSRF 初始化，下载当前 SDK 并取得包含设备、flow、challenge 的安全令牌；没有提交真实账号资料。隔离测试覆盖真实 SDK 执行、密码、TOTP、邮箱基线、手动验证码归属与重复提交、会话/工作区选择、PKCE、外站跳转拒绝及响应丢失后不重放。
- 本次没有用真实账号完成端到端授权；公开初始化和安全令牌成功不能替代真实账号验收。原项目的自动补全个人资料、手机号绑定和更广的挑战兼容未迁移；不新增这些 Web 工具入口。浏览器相关共享包暂保留供历史测试及代理工具使用；Compose 已移除 browser 服务、Socket 挂载和启动依赖，镜像不安装 Chromium，旧 worker 命令拒绝启动。
- 交互补齐：仅官方明确拒绝密码／邮箱码／TOTP 时，在同一会话提示重新输入；验证码重发仅限邮箱步骤、显式操作、每个 prompt 单次提交。连接中断、超时或不明确的响应均结束，不自动重发。验证成功的手动密码保存在同一私有记录内，后续维护重新授权使用更新值，随记录到期清除。
- 历史浏览器辅助测试已改为 HTTP 边界测试；测试使用正式协议路径，不因注入 transport 而切换到另一套授权实现。

## 架构适配边界

业务继续使用 Go；前端采用现有 React 组件，不复制参考项目的 DOM 注入脚本或运行其 Node/Python 业务。保留现有鉴权、稳定身份/版本校验、私有产物和写入确认约束。GitHub 版本使用本机代理默认值、邮箱回退匹配及浏览器下载的地方需要明确记载差异，不能静默宣称完全一致。

维护使用当前 Console 登录会话的显式委托，重启或会话失效后暂停，须重新预览保存。自动重新授权仅使用该会话中已成功导入、身份匹配且未过期的资料；缺少资料或需要人工验证码时提示重新导入，不增加原 Web 之外的恢复或短信工具。对结果不明的写入，只能在读取确认后继续，不能为了复刻原工具的自动重试而重放一次性请求。
