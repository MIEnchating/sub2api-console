## 确认问题

上游在 HTTP 或业务失败的普通 `message` 中回显本次凭据时，旧代码只做字段模式脱敏，会将实际 Token、Admin Key、Cookie 或自定义鉴权头值保留在返回错误中。服务层会消费这些错误形成失败结果，因此不能依赖浏览器或任务展示层补救。

九个隔离 HTTP 回归场景先全部失败，再修复为通过。新增场景覆盖直接回显、JSON 转义、错误截断、共享前缀凭据；同时保护原鉴权分类和 `StatusError` 的 HTTP 状态。未使用生产凭据、上游或数据库。

修复限于 `client.go` 和 `response_error.go`：JSON 解码后按当前记录的实际鉴权值替换，再执行原模式脱敏和长度截断；长值优先且一次替换，避免短值先替换后遗留长凭据片段。错误类型、鉴权判定、404 兼容和非幂等创建语义不变。自定义头按私有配置值处理，已知 Bearer/Basic 还移除去掉方案名前缀的载荷。这里只保证已配置值的直接回显及 JSON 转义，不声称识别任意编码或上游预先截断的片段。
