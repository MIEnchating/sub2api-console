# 全项目逐文件审查

本轮按文件清单检查效率、正确性、并发、凭据边界、前后端契约、测试、配置、脚本、部署定义、文档与源资源。确认的问题已修复并补充回归；其他任务同时开发的账号工作台功能保留，并按变化继续复审。不能把整个工作区的改动都归为本轮修复。

## 范围与核验

本次快照覆盖 1890 个项目文件：后端 802 个、前端 1028 个、其他 60 个。最终审查快照见 [coverage.json](coverage.json)：每项包含相对路径、大小、SHA-256 和对应审查台账。各 `*.tsv` 保存逐文件结论；同一文件发生后续变化时，旧哈希不算覆盖。清单包括已跟踪和未跟踪的项目文件，去重后核对，不以抽样或只检查 diff 代替逐文件阅读。

按用户要求忽略构建产物与打包文件，包括 `frontend/dist`、生成的路由树、压缩包、测试输出和安装的依赖。生产部署的 Dockerfile、Compose、CI 和发布脚本属于项目源文件，仍在审查范围。Git 内部元数据和本次生成的审查报告不递归计入自身覆盖率。

另核查 Git 忽略文件的清单：本机 `.env` 仅解析变量名和权限，没有输出秘密值；`data/` 的 27 个敏感运行文件仅核查路径、类型、大小与权限，没有读取数据库、备份或日志内容，也没有将其用于测试。运行数据目录与备份目录为 0700，`.env` 为 0600。不能将这些元信息检查宣称为数据内容审计。

重新核验当前工作区：

```sh
node docs/reviews/full-file-audit/check-coverage.mjs
```

输出 `pending` 或 `changed` 表示该文件新增或在审查后发生变化。完成实际复审后再更新台账和运行 `--write`；不能仅刷新哈希来消除差异。

## 性能证据

固定 fixture 的本地隔离基准，耗时受共享机器负载影响，不代表生产吞吐承诺：

| 路径与输入 | 修改前 | 修改后 |
| --- | --- | --- |
| 导入身份预览：100 个输入、1000 个线上账号 | 1394.73 ms；639.67 MB 分配 | 21.36 ms；8.66 MB 分配 |
| 目标配置读取：约 1.8 MB 无关私有载荷 | 11.47 ms；3.93 MB 分配 | 0.102 ms；1.68 KB 分配 |
| 账号投影：20 个账号的大型元数据 | 76.230 ms；34.58 MB 分配 | 19.296 ms；8.51 MB 分配 |
| 邮件历史：1000 个带时间验证码 | 2.245 s；约 152 MB 分配 | 39 ms；约 2.11 MB 分配 |
| 同策略分类：1000 条流量样本 | 7.333 ms；1.669 MB 分配 | 2.232 ms；90.97 KB 分配 |

相应优化分别消除重复身份解析、无关配置读取、重复元数据解析、平方级时间戳扫描和逐样本策略解析。前端另复用日期格式化器、建立模型及分组成本索引；未测量的路径不宣称耗时倍数。基准代码与复跑命令见各分工报告。
