# 项目效率与代码审查（2026-09-14）

本轮以当前工作区为基线进行全仓结构扫描、关键路径代码审查和自动化验证。工作区包含其他开发任务的未提交改动；以下只记录本轮确认的问题与增量修复。

## 审查范围

- 后端：业务数据与 SQLite 读写、流量排行、健康证据、路由与巡检、定价、任务持久化与清理；管理接口、上游鉴权、官方价格、Uptime Kuma、浏览器代理及工作台外部请求的响应校验、跳转和凭据边界。
- 前端：公共请求与 Query 缓存、会话清理、任务轮询、模型检测、账号 SSE、Uptime Kuma 编辑及任务生命周期、工作台会话，以及共享排序交互。
- 工程：CI 与发布检查入口、Go 回归测试发现、前端类型与静态检查、生产构建、受影响浏览器交互。

全仓扫描与关键路径审查不能证明没有剩余缺陷；本轮未使用生产数据库、真实上游凭据或通知渠道。

## 确认并修复的问题

| 问题 | 修改与回归保护 |
| --- | --- |
| 管理 API 成功响应被完整解析两次，并执行无用的错误脱敏扫描 | `adminclient/client.go` 只对非成功响应构造错误详情；保留错误业务标识、响应大小、完整 JSON 与精度校验。公开账号目录入口增加基准。 |
| 分组流量排行先扫描、去重和加载全站流量，再丢弃其他分组 | `business/traffic_ranking.go` 在 SQL 去重前按分组成员过滤；空分组不读取流量。覆盖无关分组、重叠成员、重复请求和空分组。 |
| 首次建库逐条提交 DDL，增加磁盘同步开销，失败后还会留下部分业务表 | `business/schema.go` 在一个事务内检查结构、创建表/索引并记录版本，失败全部回滚；回归保护中途索引创建失败后可清理冲突并重新初始化。保留 SQLite 原有持久化设置。 |
| 不可恢复的前端请求错误仍默认重试三次 | `lib/query-client.ts` 对不可恢复 4xx 和会话失效停止重试；408、429、5xx 和网络故障保留有限重试。通过真实 API 包装和受控网络响应验证。 |
| 缺失、null、零、布尔或对象形式的上游用量/日志 ID 被接受 | 管理接口分页证据统一验证稳定数字 ID；回归保护无效值及大整数精度。 |
| 查询跨整点时活跃时段可能超过总时段，例如一小时显示 `2 / 1` | 流量时段以查询起点划分，包含的查询终点归入最后一段；覆盖小时、日期及结束边界。 |
| 清空已结束任务日志后，迟到的终态补写会重建记录 | `taskstore.ClearLogs` 在同一事务写入删除标记、统计保护任务并删除；回归保护重启后仍不能重新写入及按截止时间清理。 |
| 追加账号时，模型读取尚未完成或失败会清空已有模型选择 | 常规模型检测等待完整模型数据后再清理不兼容选择；覆盖异步成功、失败后移除账号和确实不兼容的模型。 |
| Uptime Kuma 页面关闭后，写请求才返回任务会创建永远未结束的等待 | `use-task-completion.ts` 在卸载后立即结束等待，提示可从日志中心查看；覆盖任务返回前和返回后关闭页面。 |
| CI/发布手写的 Go 包名单遗漏模块回归测试，`./...` 默认跳过 `__tests__` | 增加 `backend/scripts/check-go.sh` 自动发现回归包，CI、发布和 README 共用入口；测试覆盖嵌套目录、去重、空目录及失败退出码传递。 |
| 排序手柄使用原生 title，键盘用户没有共享悬浮提示 | 改用共享 Tooltip，并在拖动期间禁用提示以保留 Escape 取消；新增焦点、禁用、键盘开始及取消回归，并验证现有字典/状态页排序。 |

同时修复了测试环境中只在 `beforeAll` 初始化、却在每例后清除的 PointerEvent 替身，更新已新增的账号工作台导航契约与 JSON 编辑器合法焦点白名单，并收窄无外部调用的导出以通过 Knip 检查。

动画历史的 N+1 请求怀疑经核对排除：后端历史接口主动清空任务 `Result`，详情请求用于读取真实动画产物，不能直接以摘要替代。本轮未修改这条业务链路。

## 隔离基准

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 读取 1000 个账号的成功管理 API 响应 | 约 5.42 MB、70,250 次分配 | 约 2.25 MB、35,137 次分配 |
| 2 万条流量记录中查询含 100 条记录的分组 | 约 402.8 ms、5.23 MB | 约 12.4 ms、134 KB |
| 创建新业务数据库（各 3 次公开 Open 基准） | 约 228.3 ms | 约 68.5 ms |

结果来自相同 fixture 的本地 Go 基准，使用临时数据库和受控响应。共享机器的耗时存在波动，不能直接外推生产吞吐。基准保存在 `adminclient/__tests__/response_benchmark_test.go`、`business/__tests__/traffic_ranking_group_test.go` 和 `business/__tests__/schema_initialization_test.go`。

## 验证

已确认的缺陷均有失败到通过的回归证据；性能变更使用基准和已有协议测试验证。

- 前端完整 Vitest：364 个文件、1790 个用例通过；共享机器上使用 `--maxWorkers=4 --minWorkers=1`。
- 受影响 Playwright：字典排序、状态页排序与 JSON 编辑器搜索，桌面浅色和移动深色共 26 个用例通过。
- CI/发布配置 Node 检查：19 个用例通过。
- 前端生产构建通过；全部产物约 3.47 MB，压缩后约 1.17 MB，包含所有异步模块。
- `GOFLAGS=-p=4 bash scripts/check-go.sh test` 通过，覆盖全部普通包及 23 个回归包；62 个含测试的包通过，8 个包没有独立测试文件，无 race 报告。
- `bash scripts/check-go.sh vet`、`go build ./...`、受影响 Go 文件的 gofmt 检查通过。
- 前端 `typecheck`、完整 `lint`、`deadcode`、`format:check` 通过；仓库 `pre-commit` 和 `git diff --check` 通过。

全量检查前曾暴露正在开发的工作台混合任务数据竞争，模块开发任务已修复；本轮最终完整 race 检查已覆盖修复后的混合任务。验证结果对应各检查执行时的工作区，不代表对其他并行任务后续改动的验证。

浏览器测试通过 Rsbuild 开发服务运行。后端真实 Chromium/OAuth 环境相关的隔离集成测试需要专用环境变量，本轮默认测试入口按现有条件跳过这些用例。
