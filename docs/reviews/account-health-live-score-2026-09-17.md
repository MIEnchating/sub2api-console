# 账号健康分与最近结果一致性修复

用户反馈账号 `28`（刀刀刀-天才程序员-自己进售后群-0.2）最近结果已有慢响应和网关错误，但健康分仍显示 99。

## 原因

- 当时保存的调度评估时间为 `2026-09-17T07:18:52.259265853Z`，短期 100、长期 96.5，按 `100 × 70% + 96.5 × 30% = 98.95` 四舍五入显示 99。色块已经显示约 07:24–07:26 的新请求。列表读取旧调度评估、SSE 只更新最近结果，造成时间不一致。
- 两条 HTTP 400 已被评分器识别为不参与评分的 `client_error`，API 却返回默认零分，前端又按失败兜底显示红色。它们不代表账号健康零分。
- 排查期间下一轮调度于 07:30:05 更新到约 85.94，说明原评分公式能够处理这些异常，页面更新链路需要修复。

## 修复

- 提取调度与页面共用的证据选择和评分逻辑。账号列表、详情、SSE 根据当前证据计算展示分，保留既有短期、长期及综合分公式、采样窗口、探针和熔断恢复规则。
- 页面读取使用业务库只读事务，最近结果、分类规则与评分取自同一数据库快照。读事务结束后才返回 HTTP/SSE；不保存调度评估，不推进恢复或熔断状态，不改权重、目标值及上游配置。
- SSE 完整快照同时携带评分、样本数、首字统计、时间和最近结果。前端一次更新缓存；完整快照可清除已消失的旧结果和无样本旧评分；无效或迟到的旧快照不部分覆盖新数据。
- 在数据库快照固定时记录评估时间，避免较早快照因较晚完成评分而获得更新的时间。列表请求晚于实时推送返回时，按稳定账号 ID 保留较新的健康字段与最近结果，同时正常应用账号其他字段及增删。
- 客户端请求错误返回 `score: null`，显示灰色并注明“不计入健康评分”；网关错误和致命错误保留原分值和颜色。兼容旧接口错误地返回零分的情况。
- 评分提示显示评估时间和最新有效证据时间，并说明调度状态与连续次数沿用最近一次调度评估。色块只展示最近结果，不能直接按色块数量平均得到综合分。
