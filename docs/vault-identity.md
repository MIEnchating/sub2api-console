# 密码箱稳定身份

凭据 `id` 由 Go 后端生成，与展示名称 `entry` 独立。名称仍要求唯一，但不参与身份定位。改名只更新同一行的名称，不复制凭据，不重写绑定。删除后重建同名凭据会获得新的 ID，旧绑定必须人工重新选择。

## 接口与调用方

- 密码箱索引返回 `id` 与展示名称 `entry`。新增只传名称及字段，由后端分配 ID；编辑必须传 `id`，删除使用 `?id=`。旧的 `original_entry` 不再接受，不按旧名称补找记录。
- 上游配置、手动鉴权和鉴权恢复选择使用 `entry_id`；手动填写账号密码后新增密码箱资料可传 `entry_name`，该名称只用于新建。渠道创建使用 `vault_entry_id`。
- 前端选择器以 ID 为 value、名称为 label。密码箱与上游写入租约使用同一稳定 ID；补偿操作按 ID 恢复或删除，不能误删后来同名创建的凭据。
- 鉴权恢复偏好持久保存 `vault_entry_id`。已记录 ID 缺失时明确要求重新选择，不自动按 Host 或名称换绑。验证码保留 ID；改名不改变凭据身份，删除或敏感字段变更需重新准备。

## 数据库升级

配置库升级至版本 2。PostgreSQL/MySQL 保留版本 1 的迁移及校验和，追加版本 2；SQLite 在同一事务内迁移至 `user_version=2`。首次建库也执行同一升级路径。

为每条已有凭据生成一次独立 ID，将其设为主键，名称改为唯一字段。旧恢复偏好仅在名称精确匹配时转换到对应 ID；已经缺失的引用生成独立失效标识，不重新绑定。账号密码、Host、Headers 和成功时间保持原值。再次启动不重新生成 ID。

部署升级前备份。PostgreSQL/SQLite 失败回滚；MySQL DDL 失败保留 dirty 并阻止启动，需按数据库恢复流程处理。新版本运行后禁止直接降级旧程序。前后端应同时更新，已有页面刷新后重新读取索引。

回归覆盖旧库升级、重启稳定、字段保留、改名绑定不变、重名拒绝、失效绑定和同名重建隔离；三库契约使用隔离数据库，测试不访问现有运行库。
