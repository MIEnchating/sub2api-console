# 动画质量标签与样本标注

支持统一配置大模型自动标注，也保留本地分类器和独立人工标注路径。仓库不附带已训练或已验收的权重，也不宣称检测准确率或推理耗时已达标。

## 使用方式

成功的动画预览左上角展示自动质量标签，点击预览后进入“质量标注”页签。自动结果为“正常特征”“疑似低质量”“无法判定”，历史结果缺少自动字段时显示“质量：未检测”。未启用模型评审且本地分类器未配置时返回 `unknown / model_unavailable`，得分为 `null`。生成失败仍是生成失败，不伪装成质量拒判。

查看实际提示词、动画和源码后，独立填写人工标签与判断理由；可以补充样本分组。标注保存任务 ID、账号 ID、具体请求 ID、原始生成文本、实际提示词、双方 SHA-256、自动结果快照、人工判断、操作者、时间和版本。与旧“手动通过／不通过”标记分开，不写入行为画像、健康分、糖果题判定或调度证据。重测使用新的请求，不继承人工标签。

原始生成文本保留模型输出的围栏和说明（若有），不使用注入 CSP 后的预览 HTML。生成原文上限沿用 128 KiB；缺失原文或提示词、截断、失败、前置检测及未完成批次均不能作为标注样本。账号、自定义接口、分组检测和接入前动画探活沿用各自任务身份。

保存采用版本比较；并发编辑返回 409，页面保留输入，可点击“重新读取标注”再核对。样本存入业务数据库独立的 `app_state` 命名空间，不随任务历史清理。审计仅存样本指纹及操作者，不复制源码、提示词或理由；不保存接口密钥与端点信息。

“导出标注样本”每批最多 50 条，继续点击“导出下一批样本”直到提示完成。导出所有已标注样本，包含人工 `unknown`；未知样本供复核，后续二分类训练只使用确认的 `normal` / `suspicious`。导出期间应暂停编辑以形成固定训练快照；分页不是数据库快照。

## 后端接口

接口均通过控制台鉴权并返回 `Cache-Control: no-store`：

- `GET /api/model-checks/animations/:task_id/quality?account_id=...&request_id=...`：读取实际结果及已保存标注。旧记录有完整源码和提示词时，可在此用当前模型评估；不会补造历史任务字段。
- `PUT /api/model-checks/animations/:task_id/quality`：提交 `{account_id, request_id, label, reason, source_group, version}`；首次版本为 0。理由必填，最多 2000 字，分组最多 160 字。客户端不能提交源码、提示词或替换自动预测。
- `GET /api/model-checks/animation-quality/samples?after=...&limit=50`：导出 `items` 与 `next_cursor`，每次 1～100 条。任务历史清理后仍可从此接口导出样本，但原任务标注入口不再可用。

本阶段集成到现有任务系统，不另设接收任意 HTML 的公开分类服务。标注写入仅涉及本地短事务；原文和任务读取由 Go 处理，浏览器只访问受控 API。

## 分类器与模型包

本地分类器路径只进行 Go 内存推理，不执行源码、不启动浏览器、不调用远程模型；启用统一模型评审时走文末描述的远程评审路径。环境变量 `SUB2API_CONSOLE_ANIMATION_QUALITY_MODEL` 可指定 JSON 模型包绝对路径；留空表示尚未配置。指定但不存在、损坏或不符合契约的模型阻止启动，不静默降级。启动时加载一次，限制 32 MiB；模型版本及整个原始文件的 SHA-256 随实际预测保存。

模型契约见 `backend/internal/animationquality/model.go`：schema 1、`sklearn-char-v1`、字符 3～5 gram、保留大小写、非 sublinear TF、固定平滑 IDF、L2、正类 `suspicious`，连续唯一词表索引、有限数值与合法阈值。所有字段均须显式提供（包括值为 false / 0 的字段），另含训练库和数据版本、验收报告引用、`accepted: true`。这些元数据需要发布者真实验收，布尔值本身不能证明准确率。

`pelican-v1` 绑定代码中完整固定鹈鹕骑车提示词及其 SHA-256。不同提示词记录为 `prompt-<SHA256>`，返回 `unsupported_benchmark`，不能更改名称后套用旧模型。缺失题目、格式不支持、全零特征等均有明确拒判理由；阈值两侧严格比较，边界仍拒判。有分数时称“模型得分”，不称降智概率。

预处理按 Unicode 码点，连续两个及以上 Python 空白折叠为一个 ASCII 空格，单个空白保留；不 trim、转小写或归一化。词表统计保持稀疏，按索引累加并使用稳定 sigmoid。单元测试中的合成权重仅用于验证规则，禁止用作生产模型。

## 后续训练验收

留空的样本分组自动采用源码 SHA-256，只覆盖完全重复；近似模板仍需人工归入同组。不要按渠道、模型名称、Token 数或思考等级直接生成标签。边界样本应独立复核，分歧保留 `unknown`。

训练、验证、测试按模板分组隔离，冻结提示词、训练库版本、预处理和数据版本。词表与 IDF 只在训练集拟合；阈值及拒判区间在验证集选定。真实训练模型上线前，需要训练端导出的跨语言特征／决策值／得分固定样例（误差目标 1e-8）、独立测试报告以及 CPU、输入规模、并发和内存条件明确的性能测量。当前合成数值测试不能代替已训练模型的一致性验收。

报告应同时包含样本数、正常误报率、低质量召回率与精确率、总体及按真实类别的拒判率、覆盖率和 95% 置信区间。不能排除 `unknown` 后只报准确率，不能把作品代理指标解释为模型身份或供应商降级的证明。

## 统一自动标注（模型评审）

智商检测页顶部和质量标注页均提供“自动标注设置”，共享同一份设置：开关、稳定评审账号 ID、模型、5～120 秒超时及版本。默认关闭，开启前需选择已有可用账号；后端复用账号绑定和私有凭据，前端不接收密钥。配置持久存入业务库并记录审计，旧版本保存返回 409。

启用后，账号、自定义接口、分组计划和接入前动画探活生成成功时，在原任务内追加评审阶段；每次发送实际提示词与原始源码，不发送被测账号名称、用量或接口信息。评审仅分析源码，不运行或观看动画，支持实际自定义题目。使用所选账号的 OpenAI、Anthropic、Gemini 或已有 OAuth 调用路径，评审账号执行前复核绑定和上游排除。评审全局并发为 1，等待和请求共用超时，无业务失败自动重试；原有动画生成重试不受评审失败触发。

任务中的 quality 保存 source=model_review、标签、explanation 理由、评审账号、请求／返回模型、配置版本和时间。未知、无效响应、账号失效、请求失败和配置变化均明确拒判，保留动画生成结果；不写健康、调度或人工标签。自动结果随任务保留，只有人工另行确认并保存的样本进入“导出标注样本”，不能将自动判断当作人工训练标签。历史记录不自动回填或付费重评。关闭模型评审后沿用原本的本地分类器路径，本地模型仍需真实训练验收。

GET /api/model-checks/animation-quality/settings 读取设置；PUT 同一路径提交完整设置和 version。接口沿用控制台鉴权和 no-store。

界面优先显示自动标签与理由，人工纠正和样本导出按需展开。人工表单不预填自动标签或理由，以保留独立判断。
