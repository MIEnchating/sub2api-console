# 动画质量标签与样本标注

支持统一配置大模型自动标注，也保留本地分类器和独立人工标注路径。仓库不附带已训练或已验收的权重，也不宣称检测准确率或推理耗时已达标。

## 使用方式

成功的动画预览左上角展示自动质量标签，点击预览后进入“质量标注”页签。自动结果为“正常”“降智”“无法判定”，历史结果缺少自动字段时显示“质量：未检测”。未启用模型评审且本地分类器未配置时返回 `unknown / model_unavailable`，得分为 `null`。生成失败仍是生成失败，不伪装成质量拒判。

查看实际提示词、动画和源码，确认自动标签与理由正确后，点击“确认结果并收录样本”即可自动保存训练样本，无需重新填写标签和理由。判断有偏差时展开“人工纠正”填写标签与判断理由；可以补充样本分组。标注保存任务 ID、账号 ID、具体请求 ID、原始生成文本、实际提示词、双方 SHA-256、自动结果快照、人工判断、操作者、时间和版本。独立“手动通过／不通过”功能已移除，旧记录仅保留历史读取，不参与质量判定或账号统计；不写入行为画像、健康分、糖果题判定或调度证据。重测使用新的请求，不继承人工标签。

原始生成文本保留模型输出的围栏和说明（若有），不使用注入 CSP 后的预览 HTML。生成原文上限沿用 128 KiB；缺失原文或提示词、截断、失败及前置检测不能作为标注样本。批次仍在运行时，单项 `status=succeeded` 且 `phase=completed` 即可读取和保存质量标注，无需等待其他账号或模型；仍在生成或评审的单项不可标注。标注独立保存，后续任务进度写入不覆盖它。已结束的旧任务兼容缺失或旧阶段字段。账号、自定义接口、分组检测和接入前动画探活沿用各自任务身份。

保存采用版本比较；并发编辑返回 409，页面保留输入，可点击“重新读取标注”再核对。样本存入业务数据库独立的 `app_state` 命名空间，不随任务历史清理。审计仅存样本指纹及操作者，不复制源码、提示词或理由；不保存接口密钥与端点信息。

智商检测页面顶部的“导出全部样本”一次读取所有账号的已收录样本，自动遍历每页最多 50 条的后端分页并合并下载为一个 JSON 文件。导出包含人工 `unknown`；未知样本供复核，后续二分类训练只使用确认的 `normal` / `suspicious`。任意分页失败不下载残缺文件，可重新点击从头导出；离开页面取消读取。导出期间应暂停编辑以形成固定训练快照；分页不是数据库快照。

## 后端接口

接口均通过控制台鉴权并返回 `Cache-Control: no-store`：

- `GET /api/model-checks/animations/:task_id/quality?account_id=...&request_id=...`：读取实际结果及已保存标注。旧记录有完整源码和提示词时，可在此用当前模型评估；不会补造历史任务字段。
- `PUT /api/model-checks/animations/:task_id/quality`：提交 `{account_id, request_id, label, reason, source_group, version}`；首次版本为 0。理由必填，最多 2000 字，分组最多 160 字。客户端不能提交源码、提示词或替换自动预测。
- `GET /api/model-checks/animation-quality/samples?after=...&limit=50`：导出 `items` 与 `next_cursor`，每次 1～100 条。任务历史清理后仍可从此接口导出样本，但原任务标注入口不再可用。

本阶段集成到现有任务系统，不另设接收任意 HTML 的公开分类服务。标注写入仅涉及本地短事务；原文和任务读取由 Go 处理，浏览器只访问受控 API。

## 分类器与模型包

本地分类器路径只进行 Go 内存推理，不执行源码、不启动浏览器、不调用远程模型；启用统一模型评审时走文末描述的远程评审路径。环境变量 `SUB2API_CONSOLE_ANIMATION_QUALITY_MODEL` 可指定 JSON 模型包绝对路径；留空表示尚未配置。指定但不存在、损坏或不符合契约的模型阻止启动，不静默降级。启动时加载一次，限制 32 MiB；模型版本及整个原始文件的 SHA-256 随实际预测保存。

模型契约见 `backend/internal/animationquality/model.go`：schema 1、`sklearn-char-v1`、字符 3～5 gram、保留大小写、非 sublinear TF、固定平滑 IDF、L2、正类 `suspicious`，连续唯一词表索引、有限数值与合法阈值。所有字段均须显式提供（包括值为 false / 0 的字段），另含训练库和数据版本、验收报告引用、`accepted: true`。这些元数据需要发布者真实验收，布尔值本身不能证明准确率。

`pelican-v1` 绑定代码中完整固定鹈鹕骑车提示词及其 SHA-256。不同提示词记录为 `prompt-<SHA256>`，返回 `unsupported_benchmark`，不能更改名称后套用旧模型。缺失题目、格式不支持、全零特征等均有明确拒判理由；阈值两侧严格比较，边界仍拒判。有分数时称“模型得分”，不称降智概率。

预处理按 Unicode 码点，连续两个及以上 Python 空白折叠为一个 ASCII 空格，单个空白保留；不 trim、转小写或归一化。词表统计保持稀疏，按索引累加并使用稳定 sigmoid。单元测试中的合成权重仅用于验证规则，禁止用作生产模型。

## 后续训练验收

留空的样本分组自动采用源码 SHA-256，只覆盖完全重复；近似模板仍需人工归入同组。不要按渠道、模型名称、Token 数或思考等级直接生成标签。边界样本应独立复核，分歧保留 `unknown`。

训练、验证、测试按模板分组隔离，冻结提示词、训练库版本、预处理和数据版本。词表与 IDF 只在训练集拟合；阈值及拒判区间在验证集选定。真实训练模型上线前，需要训练端导出的跨语言特征／决策值／得分固定样例（误差目标 1e-8）、独立测试报告以及 CPU、输入规模、并发和内存条件明确的性能测量。当前合成数值测试不能代替已训练模型的一致性验收。

报告应同时包含样本数、正常误报率、低质量召回率与精确率、总体及按真实类别的拒判率、覆盖率和 95% 置信区间。不能排除 `unknown` 后只报准确率，不能把作品代理指标解释为模型身份或供应商降级的证明。

## 统一自动标注（模型评审）

智商检测页顶部和质量标注页均提供“自动标注设置”，共享同一份设置：开关、稳定评审账号 ID、模型、5～120 秒超时及版本；未保存时超时默认 120 秒。默认关闭，开启前需选择已有可用账号；后端复用账号绑定和私有凭据，前端不接收密钥。配置持久存入业务库并记录审计，旧版本保存返回 409。

启用后，账号、自定义接口、分组计划和接入前动画探活生成成功时，在原任务内追加评审阶段；每次发送实际提示词与原始源码，不发送被测账号名称、用量或接口信息。评审仅分析源码，不运行或观看动画，支持实际自定义题目。使用所选账号的 OpenAI、Anthropic、Gemini 或已有 OAuth 调用路径，评审账号执行前复核绑定和上游排除，取得凭据快照后释放账号变更锁，响应完成后再次核对绑定和排除状态；发生变化时丢弃结论。自动评审复用动画检测的并发槽位：普通账号、自定义接口及独立复核共享 3 个槽位，分组任务跟随其已配置的 1～16 个并发，同时遵守全局 16 个上限；生成与评审共享额度，不再另设单并发队列。无业务失败自动重试；原有动画生成重试不受评审失败触发。

任务中的 quality 保存 source=model_review、标签、explanation 理由、评审账号、请求／返回模型、配置版本和时间。证据不足显示“无法判定”；无效响应、账号失效、请求失败、超时和配置变化显示“评审失败”，主动取消显示“评审已取消”。这些执行失败仍不生成正常或降智训练标签，保留动画生成结果；不写健康、调度或人工标签。自动结果随任务保留，只有人工另行确认并保存的样本进入页面级“导出全部样本”，未确认的自动判断不会进入训练样本；确认后保留自动评审来源，不冒充独立人工标注。历史记录不自动回填或付费重评。关闭模型评审后沿用原本的本地分类器路径，本地模型仍需真实训练验收。

GET /api/model-checks/animation-quality/settings 读取设置；PUT 同一路径提交完整设置和 version。接口沿用控制台鉴权和 no-store。

界面优先显示自动标签、理由和确认收录入口，人工纠正按需展开，全量样本导出统一放在页面顶部。人工表单不预填自动标签或理由，以保留独立判断。

### 主要效果评审规则 v2

远程评审记录 `rubric_version=animation-core-v2`，以主要主体、结构、运动和可运行性为判断依据，正常不等于没有任何瑕疵。背景云朵/草丛的长周期接缝、轻微腿长变化或次要装饰问题可作为 minor 记录，不能单独判低质量；腿脚与踏板完全不联动、主体缺失或主要动画无法运行仍属于严重缺陷。

评审 JSON 必须包含标签、理由和 `issues` 数组；每项提供 severity、scope、原文 evidence 和 impact。后端只在有 major 且属于 subject/motion/rendering 的证据时接受 suspicious，并核对引用确实来自本次源码；缺失证据、编造引用或标签与严重程度冲突返回 unknown，不改成正常。原始严重程度和证据随结果保存。结构化校验不能证明视觉准确率，静态源码仍有视觉判断局限，人工复核独立保留。旧记录保留原评审版本，不自动重评或覆盖历史标签。

2026-10-15 使用用户提供的 6 份去重原文与原提示词进行一次人工发起的线上校准，评审模型为 `gpt-6.1-sol`：预期 1 份 suspicious、5 份 normal。首轮得到 1 份 suspicious、4 份 normal、1 份因证据校验未通过而 unknown，没有把正常样本判为 suspicious；仅对 unknown 样本诊断复核一次，得到 normal，背景循环接缝被归为 minor/secondary。该复核不重新生成动画、不写回历史任务或人工标注，也未开启生产自动重试；小样本结果不能代表整体准确率，证据引用与模型输出仍可能不稳定。

### 自动生成收录理由 v3

新评审使用 `animation-core-v3`。生成后的自动评审和手动“复核”在同一次模型请求中生成结论摘要及 `basis`，不新增第二次付费请求。每项依据包含从实际题目逐字引用的 `requirement`、从原始源码逐字引用的 `evidence` 和解释实现及主要影响的 `assessment`；正常与异常结论都必须提供依据。后端校验引用存在、字段长度及原有严重缺陷规则，再自动拼成最多 2000 字的判断理由，并明确“仅依据源码，未运行或观看动画”。证据缺失、伪造引用或冲突返回无法判定，不生成可确认的二分类结果。

质量标注页展示自动理由和逐项依据，用户核对后直接确认收录，不必另填人工理由。确认和导出保留完整 `basis`、自动理由、规则版本及 `confirmed_prediction` 快照；来源仍为 `confirmed_auto`。有分歧时保留人工纠正，不能根据用户预选标签自动编造理由。未知结论说明不确定原因，不能直接确认收录为正常或异常。

质量标注布局将自动结论、评审来源和工具集中在顶部，判断理由与人工纠正在中间内容区独立滚动，样本收录操作固定在底部。原文依据默认折叠，展开后按原顺序展示要求、解释与源码引用；长源码可独立滚动并保持纯文本展示。手机端收录按钮使用整行布局，展开证据或编辑长理由不会将收录操作挤出可见区域。

旧结果及已收录样本保留原评审版本，不补造依据或自动付费重评；需要新理由时可手动点击“复核”。自动生成仍沿用已保存的评审账号、模型、开关和超时，不自动启用评审。引用校验不能证明论证正确或主要要求覆盖完整，自动收录快照仍是候选训练样本；训练前需抽检、去重和独立测试集验收。v2 的小样本校准结果不作为 v3 准确率证明。

## 检测超时的独立保存

动画、前置检测、评审分别保存超时，未配置时均为 120 秒，允许 5～120 秒整数。单项按账号、模型、阶段计时：拿到并发槽位和账号准备锁后开始，到完整响应解析结束；并发排队和账号锁等待不占用此额度。非流式采用整体超时，流式每收到有效 SSE 数据事件就重新计算等待超时，后续回复持续续期，不只重置首字；注释心跳、空行不续期，上游回退完整 JSON 时不续期。动画短暂失败的重试及退避共享原初始预算，收到流式数据后按所配置的完整间隔续期，重新排队不计时。批次仍受人工取消、服务停止及任务整体保护时限约束。字段旁的“保存”只更新当前超时，输入草稿不会立即生效；刷新或服务重启后沿用已保存值，既有评审超时不被默认值覆盖。评审账号下拉沿用共享组件，长列表支持搜索和滚动。

`GET/PUT /api/model-checks/timeouts/:mode` 使用 `animation`、`precheck` 或 `review`，写入 `{timeout_seconds, version}`，过期版本返回 409。评审超时单独保存时保留已生效的开关、账号与模型，不提交界面的其他草稿。账号和自定义接口手动检测提交 `timeout_seconds: 0`，后端创建任务时固定当前已保存值；运行中任务和恢复参数不随之后的修改变化。自动计划保留各计划显式配置的超时。

## 手动触发自动复核

质量标注页的“重新评审”按原任务、账号和请求 ID 复核已完成的单项，可在其所在批次仍运行时使用。只发送已保存的原始题目和生成原文，不重新生成动画；沿用当前统一评审账号、模型和超时。即使“生成后自动标注”关闭，只要已保存有效账号和模型，也可手动复核。

动画账号卡片底部提供“复核”及“确认收录”入口，无需打开预览。首次展示不逐卡读取评审记录，点击时读取最新复核版本再提交；已有活动复核则直接显示等待状态。卡片与质量详情共享提交状态和查询缓存，复核期间禁用重复提交，完成后同步更新卡片标签。

`POST /api/model-checks/animations/:task_id/quality/recheck` 接收 `{account_id, request_id, version}`，返回 202 和独立任务。质量读取接口返回 `recheck_version` 及最近任务的 ID、状态和消息，前端据此轮询，刷新页面可继续查看。重复提交活动请求返回同一任务，结束后提交旧版本返回 409；数据库版本条件同时防止并发认领和迟到结果覆盖。

独立复核共享动画检测的普通并发槽位，执行前重新核对原文指纹、配置及评审账号。有效结果独立保存，质量页及任务详情中的动画标签展示最新结论；生成记录原始预测不被改写，原任务后续进度保存不会覆盖复核。人工标注、已有训练样本的自动结果快照与未保存表单均保留；复核本身不创建人工训练样本。

卡片标签与质量详情按原任务、账号、请求 ID 共享质量查询缓存，复核完成后直接展示新结论，不依赖原任务详情刷新成功。已知复核仍在执行时，关闭弹窗继续查询；未打开过质量详情的卡片不额外读取质量接口。旧请求的缓存不应用到新请求，较旧质量缓存不覆盖任务已返回的更新评审。

请求失败、超时、输出格式错误或证据校验失败时，记录任务原因并保留上一次自动结果。合法的 unknown 结论仍属于一次完成的复核。取消或服务中断不自动再次调用评审，以免重复计费；用户可核对结果后再次点击复核。任务记录保存来源 ID、指纹、操作者、设置版本、规则版本和结果，不保存凭据。

## 确认自动结果并收录训练样本

自动结果为 `normal` 或 `suspicious` 且有有效评审理由时，可直接确认收录；`unknown`、无理由、错误结果或仍在复核中不能确认。该操作只写本地数据库，不重新调用上游、不重新生成动画、不自动启动模型训练。已有样本时入口显示“使用自动结果更新样本”，显式更新同一个稳定样本，保留原有样本分组，不重复新增。

`POST /api/model-checks/animations/:task_id/quality/confirm` 接收 `{account_id, request_id, version, recheck_version, prediction_sha256}`。质量读取接口返回的 `prediction_sha256` 绑定原文、实际提示词与完整预测（含评审模型、时间、规则版本）；服务端从已保存的预测提取标签与理由，不接受客户端替换。样本版本与复核版本通过资源锁和短事务再次校验；读取后评审发生变化、并发修改或重复提交返回 409，要求重新读取后核对。

确认样本的 `annotation.source=confirmed_auto`，保存 `confirmed_prediction`、`prediction_sha256`、`recheck_version` 以及确认人和时间。人工纠正使用 `source=manual` 并清除旧确认信息，旧样本缺少 source 时仍按人工标注读取。样本顶层 prediction 保留首次收录快照；训练标签以 annotation.label 为准，对应本次确认的自动评审以 annotation.confirmed_prediction 为准。后续重新评审不自动修改已收录标签，再次确认才更新样本。

导出同时包含已确认自动标注与人工纠正样本，二分类训练只使用 `normal` / `suspicious`；无需额外手动生成训练文件内容，可从智商检测页面顶部“导出全部样本”一次下载所有账号的已收录样本。未确认的自动结果不会收录。导出自动按后端游标读取全部分页并合并为一个 JSON 文件；不受当前账号、筛选、卡片分页或检测来源限制，单个账号弹窗不提供全局导出入口。任意分页失败不下载残缺文件，离开页面取消读取。

## 统一动画结论

动画结论及账号检测统计统一从质量标注产生：`normal` 对应不降智/通过，`suspicious` 对应降智/不通过，`unknown` 或缺失质量结果对应未知。人工质量纠正（`source=manual`，兼容旧人工样本未写 source）优先，否则采用最新有效复核或原自动结果。`confirmed_auto` 仅固定训练样本，不让已收录的旧标签覆盖后续复核结论。请求失败仍只计无结论。

复核与人工纠正按原任务、账号、请求 ID 更新现有样本结论，不重复累计检测次数、不改变原检测完成时间。前置检测仍使用糖果题结论，质量标签不改写模型身份、行为画像、健康或调度证据。数据库按稳定请求批量读取标注摘要，不为每条统计加载生成原文。

旧 `manual_verdict` 记录保持可读，原写接口返回 `410 animation_manual_verdict_retired`，提示改用质量标注。卡片不再提供独立“降智／不降智／清除标记”按钮。确认收录前读取最新版本，发现标签、理由或评审时间变化时更新卡片并要求重新核对，不代为确认未展示的新结论。

卡片的复核与确认收录沿用账号操作栏的共享 ghost 图标按钮，尺寸统一为 32×32px，使用中文可访问名称和键盘可见 Tooltip；页面级导出与设置沿用默认尺寸 outline 按钮。

### 生成完成后的即时预览

账号、自定义接口和分组任务在完整动画生成成功后立即发布原文和预览内容。自动评审阶段使用 `status=succeeded`、`phase=reviewing`，前端展示动画，并在质量标签与质量标注面板单独显示“质量标注中”。代码、提示词和放大预览不等待评审；评审成功、失败或超时都不重新挂载或隐藏动画。

评审中的结果不计入任务已完成数量，账号仍沿用任务互斥，人工标注与样本确认继续等待本项 `phase=completed`。同任务其他模型仍执行时，已生成模型可以继续查看；新任务尚未生成时不展示旧任务结果冒充本轮输出。

## 流式评审与失败原因

API Key 评审沿用 OpenAI Responses / Chat Completions、Anthropic 和 Gemini 的流式请求与完整结束校验；OAuth 直连评审同样逐段读取，合法的 `response.completed` / `response.done` 到达后即结束，不再等待连接关闭。隐藏 OAuth Token 的管理端预览兼容路径仍由 Sub2API 消费上游流，Console 接收已完成的受控结果。部分输出不提前解析成标签或收录理由，缺少结束事件、读取中断及执行超时均记录评审失败；质量区保持加载状态，已生成动画持续可见。

新结果分别记录 `review_request_timeout`（执行期间等待响应超时）、`review_queue_timeout`（排队期间父任务保护时限到期，未发送请求）及 `review_task_timeout`（执行期间父任务终止）。排队时间不占用设置中的评审超时；取消仍记录 `review_cancelled`。历史 `review_timeout` 没有阶段信息，界面明确标注无法还原当时的排队或请求阶段，不推测历史失败原因。点击重新评审只重发原文评审，不重新生成动画。

上游请求使用统一 `internal/modelrequest.Open`；`Parameters.Stream` 同时控制请求体、Accept、Gemini 端点及计时行为，不新增页面开关。详情见 [上游模型请求封装](upstream-model-requests.md)。
