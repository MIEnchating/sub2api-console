# 数据库性能与空间整理

2026-09-18 对业务库、任务库和配置库进行实际占用与查询路径检查。

## 保留策略

- 用户选择保持日志自动清理关闭。本次不按日期删除运行、审计或任务历史。
- 保留实际写入、错误和恢复确认。以后同一账号一小时内内容相同的自动巡检读回确认只记录一次；跨小时、实际状态或分组变化、人工操作和失败后的首次恢复仍保留。
- 保留一个已验证的部署回滚备份，使用仅属主可读的压缩归档保存数据库及对应后端程序。

## 表用途审查

原有业务库 36 张表、任务库 3 张表、配置库 17 张表，逐项核对当前 Go 代码的读写入口。

| 范围 | 结论 |
| --- | --- |
| 账号、分组、绑定、稳定上游身份、策略、调度基线及租约 | 当前业务仍使用，保留。绑定身份与展示 Host 不是重复数据。 |
| `health_samples` / `usage_records` / `account_stability_samples` | 分别服务有限健康证据、请求历史与流量统计、30 天紧凑稳定性统计，职责不同，保留。 |
| `run_records` / `runtime_events` / `operation_audit` | 分别记录运行摘要、业务事件和操作证据，不能互相替代。修复重复确认累积及索引冗余。 |
| `tasks` / `active_task_operations` / `deleted_tasks` | 任务结果、并发操作预留、阻止已删除任务被迟到写入复活，均保留。 |
| 密码箱、鉴权、会话、价格缓存及当前工作台文档 | 当前仍使用，保留。 |
| 旧 `workbench_login_profiles`、`workbench_oauth_checkpoints`、`workbench_queues`、`workbench_sms_receipts`、`workbench_source_profiles` | 当前代码无读写入口，实际均为空。启动时在事务内清理已知空表；非空旧表和未知表不删除。 |

## 体积来源

整理前业务库约 5.15 GiB，任务库约 697 MiB，配置库约 1.4 MiB。

- `operation_audit` 约 196 万行，表本身约 1.51 GiB；其中约 110 万行是自动巡检重复的无变化读回确认。
- `runtime_events` 约 151 万行，表本身约 1.24 GiB。
- 两张大表及其索引存在大量页内空隙。仅查看 freelist 会漏掉这部分空间；需要重建页面布局才能归还磁盘。
- 任务库约 242 MiB 已处于 freelist，旧数据压缩后文件仍保留了历史高水位。
- 旧备份及旧版本后端程序另占大量空间，须与工作数据库分别核算。

## 已修复路径

| 路径 | 修改与依据 |
| --- | --- |
| 首页活动计数 | 从全表 `MIN(COUNT(*),100)` 改为对子查询的最多 100 行计数；实际原查询约 172 ms，限量读取约 2 ms，结果不变。 |
| 自动读回审计 | 只对“自动巡检、成功、未远端写入、无错误、无字段变更、前后值相同”的确认做短期去重。核对最新调度结果，确保失败后的确认不会被省略。 |
| 审计日志索引 | 删除已由 `ix_operation_audit_log_recent_v2` 替代的旧索引，原占约 161 MiB。 |
| 价格变更记录 | 新增仅覆盖成功价格事件的 `ix_runtime_events_pricing_recent`，并删除旧全量类型/状态索引，后者原占约 195 MiB。查询计划验证不再扫描无关事件或额外排序。 |
| 任务日志索引 | 移除完全为搜索索引前缀的 `ix_tasks_log_listing`，搜索和列表继续使用覆盖索引。 |
| 自动任务压缩 | 新增 `ix_tasks_pending_compaction`，只索引尚未压缩的已结束自动巡检任务。原路径为了查找 100 条候选要扫描并解析历史 JSON，实测约 2.6 秒。 |
| 请求历史过期处理 | 时间条件与已有表达式索引匹配，查询计划由“定位账号后逐行过滤日期”改为索引内时间范围查询，保持原有 30 天请求证据策略及 NULL 日期语义。 |
| SQLite 并发 | 三个库复用单写连接、独立只读池及 immediate 写事务。任务历史分页使用只读事务，避免占用写连接。 |

## 验证要求

- 单元与回归覆盖相同确认、实际写入、人工操作、失败恢复、小时边界、空数据、历史索引替换、旧非空表保护及查询计划。
- 连接池测试覆盖并发读改写、读取快照、禁止只读事务写入、取消等待与后续写入。
- 发布执行完整 `bash scripts/check-go.sh test`、`bash scripts/check-go.sh vet` 和 Go 生产构建。
- 离线整理执行完整性检查、每表行数核对、`VACUUM`、统计信息优化和 WAL checkpoint；不运行业务调度或调用真实上游。

## 账号列表查询优化

同日进一步检查账号管理页面的读取链路：`GET /api/accounts` 在同一个只读快照中读取账号，并计算当前健康分。原健康分计算复用了调度决策查询，对每个账号额外查询三类历史写入时间。约 197 万条审计记录中，并发变更记录很少，逐账号寻找最近一次并发写入成为主要耗时。三个时间仅供调度冷却使用，健康分展示不依赖它们。

- 新增只读取历史决策状态的查询供健康分展示使用，保留账号、分组和决策失效时间筛选及历史状态校验；调度仍使用包含写入时间的完整查询。
- 健康样本使用已有的账号与标准化来源索引，按账号、来源读取到足够的独立证据后停止。保留跨分组去重和流量、探活各自的样本窗口。
- 无需新增索引或修改数据库保留策略。
