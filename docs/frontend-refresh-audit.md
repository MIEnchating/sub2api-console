# 已有内容的后台刷新检查

检查范围：前端页面、弹窗与共享组件中 `refetch()`、`isFetching`、加载占位和清空结果的调用链。区分首次读取、相同目标的后台刷新、切换目标和新任务执行。

## 已修复

| 位置 | 问题 | 当前行为 |
| --- | --- | --- |
| New API 模型价格 | 比较、批量预览、单项同步均无条件重取同一价卡 | 使用同一查询配置复用有效缓存，按后端到期时间重新读取；手动强制刷新独立保留 |
| 模型价格比较状态 | 后台查询使已有结果变成“比较中” | 保留上次比较结果，刷新失败在表格外提示；不完整价卡不能用于同步 |
| 远程模型价格表 | 刷新或刷新失败时移除分页 | 保留模型行与分页，不重建已显示内容 |
| 模型检测 | 刷新共同模型时用加载文案替换模型列表 | 首次加载和后台刷新分开；保留列表、选择与滚动容器，刷新中或失败时禁用检测 |
| 开户 Key 清理 | 重新扫描将预览置空，弹窗缩小并重建表格 | 保留预览和宽度，刷新按钮表示进度；扫描中或失败时禁用删除 |
| New API 渠道模型选择 | 重取相同渠道模型时清空背景已选数量和弹窗列表 | 保留已有内容；成功后去除已失效模型，失败时提示并禁止确认旧目录；更换 API 地址仍清空不再属于该目标的数据 |

## 其余调用链

- 账号、上游、分组、价格管理、日志、流量排行、系统信息、配置、密码箱与巡检页面：刷新状态用于按钮，已有查询数据继续参与渲染；首次加载使用 `isLoading` 或缺失数据判断。
- New API 平台快照与原始价卡：已有快照时保留内容，只有无数据时显示加载占位。
- 分组探活模型、账号探活模型、请求记录的账号处置：刷新状态用于按钮或禁用依赖最新状态的操作，已有选项或账号信息不被清空。
- 账号模型同步在目录版本冲突后重取预览、任务结束后刷新关联资源、用户重新执行探活：这些请求用于读取新的业务结果，保留其刷新行为。
- 查询目标、搜索条件变化造成的首次读取不复用其他目标的数据，避免跨账号、跨平台串用。

## 回归覆盖

- `model-price-catalog-query.test.ts`：缓存到期、不延长后端有效期、刷新不完整、并发去重与平台隔离。
- `model-price-cache.test.tsx`、`pricing-cache.test.tsx`：比较与同步复用缓存、失败后保留结果、手动强制刷新、分页节点稳定。
- `model-refresh.test.tsx`、`channel-model-refresh.test.tsx`、`key-cleanup-refresh.test.tsx`：刷新中的既有内容、勾选与失败时操作限制。
- `e2e/__tests__/background-refresh.e2e.ts`：桌面及手机上的真实页面请求次数、列表与分页节点保留、渠道选择、Key 清理弹窗尺寸及操作限制；所有 API 均隔离拦截。
