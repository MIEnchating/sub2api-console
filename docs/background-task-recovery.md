# 后台任务中断恢复

后台任务区分用户取消、服务停止和业务失败。用户取消先持久保存取消结果，再通知执行器停止；服务重启、部署退出和进程崩溃属于中断，具备完整恢复参数的任务在后端启动后继续使用原任务 ID 执行。普通接口错误、超时、策略拒绝和用户取消不会因此自动重试。

## 恢复范围

| 任务                         | 恢复行为                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------- |
| 账号动画、前置检测及组合检测 | 保存稳定账号、绑定指纹、模型、超时及检测问题，保留已完成账号/阶段，只执行未完成项                  |
| 终端续接检测（已移除） | 保留历史结果，不再创建或恢复；含终端阶段的旧组合任务须重新提交 |
| 任务管理中的检测任务         | 校验原配置 ID、版本、管理目标和已开始执行的分组成员/账号绑定；保留已完成阶段结果               |
| 账号倍率同步                 | 保持原账号范围，重新读取当前上游倍率及管理端状态，通过已有版本校验和读回逻辑避免盲目重放写入       |
| 自动/手动巡检                | 保持原任务 ID 和请求范围，重新同步管理目录并按当前策略规划；解除只属于中断轮次的未完成阶段到期标记 |
| New API 账号模型自动化预览 | 仅恢复只读预览，重新读取当前分组成员与模型目录；正式渠道及价格写入不自动重放，需重新预览确认 |
| 手动日志清理 | 分批提交，关闭页面不影响执行；人工取消保留已提交删除。服务停止或崩溃时保留中断原因，不自动恢复原任务；可重新按期限清理剩余记录 |
| Uptime Kuma 接入验证及监控、资源写入 | 人工取消按任务 ID 停止排队或正在进行的请求，保留已确认的资源 ID 和部分结果；服务停止标记中断，不自动恢复或重放写入，需先刷新核对远端状态 |

恢复沿用各领域的并发限制、账号互斥及巡检租约。容量不足或账号仍被使用时等待再调度；恢复调度本身不占用长期清理任务的执行槽。检测任务的配置、成员、绑定或管理目标变化时保留已有结果并显示具体恢复失败原因，要求重新提交。自动巡检或自动倍率同步被关闭、当前运行模式不再允许执行时不继续旧自动任务。

自动巡检在恢复入队及取得执行槽位后均核对启用状态，执行使用调度器本次读取的配置，不沿用入队时的配置快照。排队期间关闭自动巡检，旧自动任务在管理目录同步前失败；手动恢复仍可在自动巡检关闭时执行。当前配置读取失败或调度未能启动时保留任务原有结果并记录具体原因，避免用启动错误覆盖已保存的历史明细。

New API 运营计划的预览、正式执行和后续状态读取共享计划生命周期。单独运行的计划在请求返回后不随浏览器关闭而取消；任务组取消会传递给其子任务，包括刚落库、尚未向任务组暴露 ID 的排队任务。服务停止使用中断原因停止后续执行，并等待跟踪协程退出；超出关闭期限时不提前关闭数据库。单次状态读取最多 5 秒，任务已删除立即停止跟踪，其他读取错误连续 3 次后停止并记录原因。任务组直接等待计划完成通知，不另行每 100 毫秒读取完整子任务结果。已经发生的远端写入不能撤回，正式写入中断后仍需核对并重新预览。

通用任务取消接口在通知执行器前，先在任务库事务中持久化取消状态、保留已保存结果、删除恢复检查点并释放任务预约；排队、运行及等待输入的普通任务都适用，不要求任务本身支持恢复。持久化失败不通知执行器，也不返回取消成功。验证码挑战保留原有专用取消入口。

Uptime Kuma 任务使用可按 ID 取消的执行器，排队期间取消不连接远端。运行中取消会中止当前 HTTP 或 Socket.IO 请求；已经送达远端的写入不会因此撤销，未收到确认的操作不能当作未执行。主体写入已确认、后续关联中断时保留主体 ID 和已保存标记，并停止后续请求。人工取消与服务停止分别记录取消和中断原因；不保存管理凭据作为恢复参数，也不自动重新连接并重放写入。开始时进度保持 0%，不以固定 20% 代替实际完成情况。模板参数下发（`uptime-kuma-template-distribute`）同样不自动恢复：执行前核对已确认影响范围，每项执行前复核当前模板、绑定及监控版本；保留已完成、失败、跳过和未执行项目。进度按实际完成项目数量计算；失败、取消或服务停止后先核对远端状态，再重新预览并人工确认下发。

运营子任务创建时把所属任务组的运行任务 ID 保存到私有恢复参数；独立计划明确保存空 ID。任务组人工取消后，排队子任务无需获得执行槽即可持久化取消。恢复调度前及实际执行前再次核对父任务身份和状态；父任务已取消时子任务也记为取消，不读取账号模型，不重放远端写入。父任务缺失、身份不符或已经停止时拒绝单独继续子任务。任务组编排本身仍不支持自动恢复，服务重启后需核对并重新运行；旧计划预览若没有记录归属字段，无法区分独立运行与任务组成员，返回具体原因并要求重新运行计划。新独立预览及没有计划归属的旧独立预览保持原有只读恢复规则。

运营计划和任务组的配置读改写使用私有配置库的短事务。任务组成员校验与保存、删除计划与清理关联成员分别原子提交，失败整体回滚；未变化的设置值不重复写入。计划启动在事务外读取远端渠道，记录运行时间时重新核对该计划的原配置，只更新对应条目。启动期间被编辑或删除的计划返回具体冲突原因，不启动正式执行；已创建的只读预览可能留在任务历史中。其他计划的并发新增或编辑不会被旧快照覆盖。已经接受的执行仍使用本次固定范围，后续编辑配置不等同于取消执行。

任务创建、计划保存及恢复共用范围校验：分组为 1～50 个不重复稳定 ID，渠道最多 50 个且必须保留不重复稳定 ID 和有效版本，模型选择和价格来源也按相同规则校验。旧参数缺少价格来源时沿用官方来源默认值。领域执行在开始渠道上架前校验完整渠道集合，避免部分写入后才发现返回了重复或范围外渠道；生产管理适配层仍逐项核对远端 ID。计划编辑保留后端当前的上次运行时间；定时方式未变化时保留原下次运行时间，调整间隔、每天时段或重新启用时重新计算，关闭定时则清除下次运行时间。

可恢复的动画和前置检测阶段只把已返回、已保存的结果视为完成。进程在请求到达上游后、结果落库前崩溃时，无法确认该次生成是否完成，恢复会重新请求该未完成项，可能产生额外生成用量。已移除的终端检测不适用此续跑规则。

## 持久化与安全边界

`task_recovery` 是任务库中的私有辅助表，首次建库或旧库启动时增量创建，不修改或清空现有任务。版本化参数与任务状态在同一事务中保存；完成、业务失败和手动取消后移除恢复参数。恢复信息不会随公共 Task JSON 返回，也不会进入浏览器存储。管理目标和账号绑定只保存指纹，不复制 Admin Key、API Key、Token 或密码。

启动准备逐项在本地写事务中复核活动状态、检查点存在及删除标记，保留任务互斥并直接更新中断标记；不把完整结果和检查点读入 Go 后再解析、序列化和写回。待恢复列表只保留稳定任务 ID。每次分发（包括容量等待后的再次尝试）从同一数据库快照读取当前结果与检查点，再交由领域逻辑校验；已取消、已结束、已删除、检查点已移除或已经开始运行的任务不再分发。损坏的结果或检查点保留到逐项校验时明确失败，不因单项损坏阻断整个服务启动，不猜测或重建恢复参数；检查点损坏时保留已有可读结果。数据库读写错误仍使启动准备失败。

恢复任务进入领域执行器的有限队列后只保留任务身份、恢复参数摘要及已校验的领域输入，不持续保留完整结果。取得执行槽位后有界重读结果和检查点，核对身份及摘要，再交由领域执行；已取消、已结束或检查点已移除的任务跳过，账号及计划占用仍须释放。排队期间服务停止保留当前进度和已完成结果，人工取消不自动恢复。重读数据库失败时记录具体错误并保留持久状态，等待下次启动恢复，不用空结果覆盖或无限重试。

SQLite 更新中断标记时仍需处理结果 JSON；运行中任务、领域输入及非恢复任务的队列仍可能持有各自明细，不能将 Go 分配减少或待处理列表变轻解释为整个进程内存有固定上限。恢复入队及执行各读取一次完整结果，优化针对等待期间的持续驻留，并不承诺累计分配或完整执行耗时下降。

自定义接口动画依赖仅驻留内存的临时 API Key，因此不保存恢复参数；OAuth 授权、刷新令牌、安全写入、开户、购号、通知投递等未提供专用恢复协议的任务不会自动重放。中断记录保留已有明细并明确说明需重新提交。普通旧版本任务没有完整参数时也不根据任务名称、当前页面或不完整结果猜测恢复范围；已经结束的历史取消任务不会被重新激活。

日志清理涉及独立的任务库和业务库，目前没有跨库原子提交的恢复计数检查点。进程突然退出时，最后保存的进度可能落后于已经提交的删除，因此不把原任务恢复为完整成功，也不补造删除数量。重新清理按新任务的固定截止时间执行，仅统计该任务实际提交的删除；自动清理开关与保留期限不因手动清理而改变。

## 验证

回归覆盖服务停止与手动取消的区分、崩溃后的任务库重开、连续重启、取消与旧 worker 保存之间的竞争、恢复容量等待、配置变化拒绝、已完成账号不重复生成、旧终端任务拒绝恢复且保留历史结果、倍率读回以及巡检目录刷新。默认测试仅使用临时 SQLite 和隔离 HTTP 服务。

后端检查：`bash scripts/check-go.sh test` 和 `bash scripts/check-go.sh vet`。
