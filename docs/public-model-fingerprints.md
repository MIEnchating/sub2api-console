## 检测方法与判定边界

**KBF**：按域字典序、原域内顺序每批最多 10 题，使用原始填空模板和固定 system，温度明确为 0，输出上限每题 80 Token。保留参考自测的总数与差异数，以单侧 99% Clopper–Pearson 上界为噪声基线，对目标差异数做单侧二项尾概率检验，阈值 0.05。计算保留小概率数值精度，不把 p 值解释成“是真模型的概率”。保留原域的相对／绝对容差、绝对域 half-away-from-zero 取整、有效数值区间。

Go 解析器只接受明确编号和单一数值，比上游“取最后一个数字”的策略更严格；重复编号、解释性文字、非有限数值不作为答错或答对。参考和目标有效覆盖均至少 50%；请求缺失、截断、失败、元数据缺失或同一检测方法中的协议／返回型号变化均为无法判定。没有自动重试，也不按与参考是否相符选择回答。

KBF 参考只记录 system 与 temperature，未完整记录原采集过程自动探测的思考抑制参数；本次不猜测抑制策略、不自动切换参数。本次发送默认思考、非流式、固定输出预算，并逐请求保存实际要求的参数。版本变化、量化、提供商及隐藏提示差异仍可导致偏离；移植解析和重试策略与原项目也有差异。因此这只是条件性的公开基线比较，未经本项目对所有真实提供商验证，不提供准确率保证。

**分词**：使用 modelprint 的逐字原始英文、中文、代码、Unicode 提示词，各文本连续两次，再发送 `a` 基准，共 3 次。只在响应协议、返回型号和两次输入计数稳定、输入计数有效时计算差分；同一方法跨单元元数据变化亦不可比。输出限制为 1 Token，因该限制产生的 `length`／`max_tokens` 是预期行为，仅采集输入用量，不冒充完整能力回答。计数缺失不补零。相同差分最多说明分词器相容，不能认证具体权重；差分不同也可能源于计量或模板变化。

**分布**：四类数字任务（1～100、1～10、协同选数、反协同选数）×中英文，逐轮交错，每单元 30 次，温度 1，无 system，输出上限 16。固定子集、严格单个整数解析，不使用原来的 `short-answer-distribution-v1` 提示词或默认温度去比较公开分布。有效、无效、请求错误、未执行分开；每单元至少 20 个有效样本且元数据一致才计算 base-2 JSD。公开四舍五入的概率先归一化。全部单元可比且元数据一致才展示平均 JSD。该子集没有独立校准的真伪阈值，距离只作证据，不转换真假百分比。

统一结论为：

- **与公开参考一致**：KBF 未检出超出参考噪声的差异；若还有分词，须同时完整且一致。
- **与公开参考显著不符（疑似冒充）**：完整 KBF 比较的 p < 0.05；仍需核对推理配置、版本、路由等原因，不等同权重鉴定。
- **无法判定**：参考或采样不足、参数不兼容、方法只有分词／未校准分布、方法间冲突等。展示具体理由，不把缺失包装成正常或异常。

## 协议、任务和兼容

参数经 `internal/modelrequest.Open` 发送。公开参考使用 Chat Completions、Anthropic Messages 或 Gemini 原生映射；不自动尝试多个协议或参数直到得到“好结果”。鉴权、限流、参数不支持沿用检测停止规则。OAuth 固定请求无法重现公开参考要求的温度、system 和输出上限，跳过额外请求并明确说明不兼容，不静默套用 API 基线。常规检测仍可继续。

任务沿用账号互斥、排除策略、凭据保护、取消、超时和临时 Key 清理。添加账号最多 10 分钟，独立模型检测最多 30 分钟；耗时分布模式可能因整体上限产生部分结果。请求全部成功就是执行完成，参考差异不把任务标为请求失败；不向健康、调度、自动熔断或清理写入证据。

独立新前端提交 `fingerprint=true, public_reference=true, behavior_fingerprint=false`。添加账号的 `verification` 自动包含公开参考。`behavior_fingerprint` 与旧 `fingerprint/reference` 探活模式仅保留已有协议和历史兼容，UI 不再提供单独入口。旧报告没有公开参考字段则不补造结论。

## 检测项并发（verification-v6）

账号模型检测和添加账号探活共用检测执行器，每个账号／模型组合最多同时执行 4 项，所有这类检测任务共享 16 个请求槽位；同账号的多个模型仍依次执行，既有任务互斥不变。每轮能力检测和每类采样阶段先执行首项检查接口与参数支持，之后开放并发。排队不计单项请求超时；原任务总时限仍有效。

独立能力题、知识边界批次可并发；普通分词同文本的首次／复测、公开分词同单元的两次采样／基准、公开分布同单元的重复采样保持先后顺序，不同单元可并发。原始题目、温度和输出上限不变，计划与最终报告仍按题库顺序展示；实际请求开始、完成顺序可能不同，不承诺并发与串行采样的分布完全相同。旧行为指纹保持原有串行交错顺序。

报告记录 `probe_concurrency` 上限和完整 `current_probes` 数组，旧 `current_probe` 兼容字段只表示其中第一项。前端展示全部在途项，结束后清空运行状态。进度由单个协调器发布不可变快照，结果依计划索引整理，不依赖完成先后。遇到限流、鉴权或不支持参数错误停止派发并取消本组合在途请求；人工取消也保留已完成证据，收齐所有启动请求后才允许调用方清理临时 Key。未发送项不补造回答或计为答错。

### 请求完成与证据完整性

“已执行”包含成功和失败的请求，不等同于全部成功。证据弹窗单独显示请求失败数量，并提供“查看失败项”定位入口。知识边界无法判定时记录实际阻断原因：请求失败／未返回、回答截断、可解析数值覆盖不足、返回型号或协议不一致、缺少元数据、参考自测基线不可用；保留有效题数，不把已结束的失败请求计为有效答案。历史报告沿用原结论，可依据已保存的失败项补充具体说明，不重发请求或改写历史结论。

接入前探活收到终态创建响应时直接结束等待；运行中任务在后台标签页继续轮询。检测请求结束但临时 Key 仍在清理时，操作按钮显示“正在收尾”，收到任务终态后恢复重试入口，保持清理与新任务互斥。
